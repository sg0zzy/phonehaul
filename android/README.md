# Android client

The native Android client supports Android 11+ (API 30+). It uses CameraX and ZXing to scan the receiver's QR, pins the receiver TLS certificate fingerprint, and rejects non-private IPv4 endpoints. The app has no accounts or background synchronization.

Selection uses Android's document picker for multiple files, the tree picker for folders, and a MediaStore browser for photos and videos. Choosing a folder adds its files directly, including files in subfolders, without adding the source directories as transfer items. Each file keeps the selected folder name in its destination path, so the computer recreates that structure. Empty folders are not transferred. The MediaStore browser may show only the items Android grants permission to access. Android 11+ restricts some tree locations, including the storage root and Downloads root.

COPY leaves sources unchanged. MOVE starts with the first selected file and processes the rest one at a time. For files with a reported size, Android calculates SHA-256 while uploading and deletes each supported source only after the receiver acknowledges a matching size and hash for a committed or identical destination. Files without a reported size require a size and hash pass before upload. An active outgoing transfer runs with a `dataSync` foreground service, an ongoing notification, and a CPU wake lock so the screen may turn off during the transfer. On Android 13+, the app asks once for notification permission when starting a transfer; declining it does not stop the transfer. The service and wake lock stop when the transfer finishes, fails, or is cancelled. Android 15+ limits background `dataSync` foreground service time to six hours per 24 hours. MediaStore deletion uses Android's confirmation prompt after files are committed. Skipped, failed, and uncommitted files remain on the phone. Source folders remain in place. If deletion fails or is declined, the computer copy stays intact and the app reports the original as remaining.

After pairing, the app also receives computer files while its ViewModel is running. The computer UI accepts files and folders by drop or picker and sends their individual files in queue order. Every file appears directly in public `Downloads`; folder contents are flattened, and original relative paths are retained only as transfer metadata. This destination is fixed and needs no storage permission or folder picker. MediaStore holds an incoming file pending until its size and SHA-256 pass verification. An existing name gets a numeric suffix, such as `report (1).pdf`. Empty folders are not preserved. Receiving still requires the Android app to remain open; incoming transfers have no foreground service or partial resume.

Build with `ANDROID_HOME=/path/to/Android/Sdk ./gradlew :app:assembleDebug :app:testDebugUnitTest` from this directory. Install `app/build/outputs/apk/debug/app-debug.apk` on a phone. A real phone and receiver on the same LAN are needed for camera, provider deletion, and transfer validation.
